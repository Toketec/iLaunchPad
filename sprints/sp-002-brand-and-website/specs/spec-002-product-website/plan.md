# spec-002：实现计划

- [ ] `apps/website/README.md` — 本地运行、目录与 SSOT 入口
- [ ] `.github/workflows/pages.yml` — 从主仓库部署静态目录到 GitHub Pages
- [ ] `apps/website/dist/index.html` — 语义内容、SEO、弹层与演示结构
- [ ] `apps/website/dist/styles.css` — 品牌样式、响应式、焦点和减少动态效果
- [ ] `apps/website/dist/script.js` — 语言、弹层和演示状态
- [ ] `apps/website/dist/assets/` — 仅项目原创官网素材
- [ ] `apps/website/tools/build-showcase-video.sh` — 从真实系统录屏重建定位缩放、柔和转场与双格式成片
- [ ] `apps/ilaunchpad/Sources/iLaunchPad/LayoutStore.swift` — 保留既有隔离采集能力；本轮真实素材改用已备份后初始化的用户布局

## 实现顺序

1. 把网站工作区归入 `apps/website/`，移除嵌套 Git 与工具专属托管身份，由根仓库统一版本管理。
2. 以冲刺原型重整语义结构、首屏信息和真实 Release/源码入口。
3. 对齐雾白/深海蓝/火焰橙视觉、响应式和可访问性。
4. 移除网页模拟启动台、虚构案例和旧主题素材，建立统一真实截图/录屏空白槽。
5. 实现中英文与移动导航，保证脚本失败时核心内容与链接可用。
6. 补充独立品牌、真实能力和兼容迁移 SEO。
7. 本地浏览器确认风格与框架后，先备份用户布局，再按可核对的 macOS 默认布局资料初始化当前客户端；首页保留一个文件夹与一个空位，使用系统原生录屏分别采集分页、搜索、拖拽换位、文件夹开合与长按编辑。每段以真实操作位置为焦点进行缓入缓出的定位缩放，段间柔和过渡，输出无字幕主导览和交互短片；接入网站后由用户决定是否恢复布局与发布。
8. 通过根仓库 GitHub Pages 工作流发布 `apps/website/dist/`，分别记录提交、工作流部署和用户视觉签收。

## 测试计划

本轮完成框架与真实客户端媒体接入，并在本地浏览器检查桌面、移动、键盘、减少动态效果、无脚本、中文/英文、所有 CTA 和“无模拟客户端画面”；随后由 GitHub Pages 工作流发布并核对公开地址。原布局保留可恢复备份，用户验收初始化画面后再决定是否恢复。
