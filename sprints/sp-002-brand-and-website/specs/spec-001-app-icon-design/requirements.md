# spec-001：应用图标设计实现

## 架构落地边界

- 细功能：ICON-01～08；产品规则见本冲刺 [SPRINT-features](../../docs/SPRINT-features.md)。
- 当前架构基线：[模块职责](../../../../architecture/architecture.md)与[运行配置](../../../../architecture/runtime.md)。
- 进入状态：冲刺 1 已具备设置入口、`appIconStyle` 偏好、运行时 Dock 图标更新和一个用户指定的白底石墨火箭初始包图标。
- 本规格实现程度：建立四款原创图标的视觉体系、稳定 ID/名称、原稿与发布资源、连续圆角封装及构建打包契约，并将海蓝版设为当前包图标。
- 退出状态：客户端可消费一套可重建、可回退、可分发的四款图标目录；冲刺 1 的选择与持久化行为不在本规格重复实现。

## Context from Dependencies

### sp-001/spec-007（外观与偏好）→ 运行时选择契约
- `appIconStyle` 保存稳定字符串 ID，默认 `ocean`。
- 设置界面读取图标目录并显示选择状态。
- 选择即时更新 Dock/应用切换器；启动时恢复。
- 未知或已删除 ID 会迁移并回退 `ocean`。
- 访达图标由包内 `AppIcon.icns` 决定，不在运行时改写。

## 局部实现方案

`AppIconSources` 保存四款原稿和生成提示；`prepare_app_icons.swift` 在每次生成前清理旧发布图，只裁掉母图外部预览留白，将单一底板缩放到 824/1024 的 macOS 图标安全区并施加一次连续圆角遮罩，输出 `AppIcons`。`AppIconCatalog` 冻结 ID、名称和资源名。构建脚本将四款目录打包，并从同一份 ocean 发布图生成包内 icns，确保 Dock、访达和启动台网格不因资源链不同出现额外外框或尺寸差异。

四款共享火箭构图，默认 ocean；视觉名称依次为玻璃蓝、玻璃紫、玻璃黑亮底、玻璃白暗底，稳定 ID 保持 ocean、violet、obsidian、porcelain。紫色款是全系列材质与光照基准：底板只保留淡淡、低对比的玻璃层次，火箭仅用面内渐变塑形，不自发光，周围不得出现光晕、霓虹描边或火焰外溢。玻璃蓝使用近白冷蓝底与深宝石蓝主体保证小尺寸清晰；黑色火箭使用明亮玻璃底；暗色款使用午夜石墨玻璃底、珍珠银白主体与烟熏深色舷窗，通过明暗对比辨识而非发光。四款火箭比例一致；主体、火焰、底板在 16px～1024px 下分别检查。所有素材为项目原创，不引入竞品或系统受保护图形。

## 数据与接口

无网络 API 或数据库。资源契约为稳定 ID → 中文名称 → PNG 文件名；`appIconStyle` 只保存 ID。图像文件不包含用户布局或应用清单。

## 边界

- 不改变冲刺 1 的设置窗口、偏好保存或 Dock 更新业务逻辑。
- 不设计官网页面；官网只消费已批准的品牌素材。
- 不承诺图像生成即等于品牌视觉验收通过。
- 不删除历史素材备份或修改已安装技能、模板。

## 验收条件

- 四个 ID 唯一，均有原稿、发布图、名称与提示来源；默认和回退为 ocean。
- 发布图尺寸、透明通道、连续圆角和小尺寸辨识通过检查。
- 构建产物包含完整目录，包内初始 icns 使用默认海蓝火箭。
- 运行时选择、重启恢复、资源缺失回退与访达边界通过实机验收。
- 素材原创边界和分发许可说明清楚。
