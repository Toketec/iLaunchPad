# 冲刺 2：用户场景

## 用户旅程总览

用户在客户端设置中选择喜欢的原创图标，系统立即呈现并在下次启动恢复；访客从搜索、分享或项目文档进入官网，在首屏先理解 macOS 26、27 的 LaunchPad 缺口与 iLaunchPad 的补位价值，再从真实截图/录屏判断现代外观和操作体验，确认当前获取状态与未来扩展方向，最后决定下载开发预览、查看源码或参与项目。

| ID | 角色与触发 | 期望结果 | 对应功能 |
|:---|:---|:---|:---|
| U01 | 用户打开“应用图标”设置 | 看见四款同构图预览、名称和当前选择，选择后即时更新 | ICON-01～07 |
| U02 | 已保存图标资源缺失或 ID 未知 | 自动迁移并回退玻璃蓝，设置仍可用，布局不变 | ICON-07 |
| U03 | 新访客首次进入官网 | 首屏理解 macOS 26、27 缺失 LaunchPad、产品如何补回并增强及开发预览状态 | SITE-01、04、05 |
| U04 | 访客想先感受交互 | 查看当前版本真实截图或录屏；素材未拍摄时看到清楚的待补说明，不被模拟画面误导 | SITE-02、03 |
| U05 | 访客尝试获取应用 | 进入真实存在的 GitHub Release 或源码页，并看到开发预览边界 | SITE-05 |
| U06 | 原 LaunchOS 用户搜索迁移方案 | 在兼容迁移事实中发现 iLaunchPad，同时清楚它是独立项目 | SITE-08、09 |
| U07 | 移动设备、键盘或减少动态效果用户访问 | 页面可读、可操作，无横向溢出和强制动效 | SITE-07 |
| U08 | 贡献者检查项目依据 | 从官网或 README 进入冲刺 2，能追溯设计、实现和验收边界 | SITE-10 |

## 异常与边界

- 官网脚本失败时保留核心定位、功能、素材状态和获取入口。
- 语言偏好只属于当前浏览器，不写入客户端布局。
- 图标选择失败不改动包内资源和用户布局；回退可恢复，错误不伪装为成功。
- 第三方名称仅帮助说明兼容迁移，不进入品牌主标题、图标或产品名称。
