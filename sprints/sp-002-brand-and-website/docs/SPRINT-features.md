# 冲刺 2：品牌标识与产品官网

## 目标与边界

以两个独立功能板块建立 iLaunchPad 的原创品牌表达：一组可在客户端选择的应用图标，以及一个让访客在首屏理解“为 macOS 26、27 补回并增强 LaunchPad”这一核心价值、再从真实客户端素材判断体验的静态官网。图标设计实现由 spec-001 负责，官网设计实现由 spec-002 负责；不再混入冲刺 1 的偏好规格，也不把官网作为根目录游离项目维护。

冲刺 1 的白底石墨火箭保留在历史里程碑；冲刺 2 将玻璃蓝设为当前包图标、默认与回退，并精简为玻璃蓝、玻璃紫、玻璃黑亮底、玻璃白暗底四款。官网获取入口必须与公开仓库和 Release 的真实状态同步；开发预览须明确说明签名、公证与系统要求，不放置无效下载按钮。网站是否发布及访问权限由本规格单独记录。

## R1 应用图标设计实现（ICON）

- 延续扁平火箭识别，形成玻璃蓝、玻璃紫、玻璃黑亮底和玻璃白暗底四款；玻璃蓝为默认与回退，四款比例一致。
- 玻璃紫作为全系列光效基准：底板只保留淡淡、低对比的玻璃层次，火箭通过面内渐变塑形，不自发光，周围无光晕、霓虹描边或火焰外溢。
- 主体在小尺寸仍清楚，保留均衡留白；轮廓柔和、现代雅致，不出现过小主体、尖锐武器感或类似系统垃圾桶的蓝色。
- 发布图统一使用 macOS 连续圆角封装，保留透明外缘；原稿、生成提示、发布素材和稳定 ID 可追溯。
- 设置中展示四款预览、名称、选中状态和辅助功能标签；选择即时用于 Dock 与应用切换器并持久化。访达使用玻璃蓝包图标。
- 缺失资源或未知 ID 回退玻璃蓝，不因图标选择损坏签名资源、用户布局或应用启动。
- 冲刺 1 spec-007 只拥有“选择、保存、恢复”的偏好行为；本规格拥有视觉方案、四款素材、发布封装和目录契约。

## R2 产品官网设计实现（SITE）

- 首屏在常见桌面视口内同时说明 macOS 26、27 缺失 LaunchPad 的问题、iLaunchPad 的补位价值、开发预览状态，并为当前版本真实产品画面保留首要位置。
- 页面按“补回熟悉能力 → 现代外观与操作增强 → 本地与迁移优势 → 未来高级能力”展开；每段区分现有能力与未来方向，不堆砌空泛形容词。
- 客户端画面和动作案例只使用同一版本真实截图或录屏；框架阶段一律显示带用途、比例和拍摄内容标注的空白素材槽，不用网页模拟界面或虚构案例填充。
- 获取入口反映真实状态：公开 Release 存在时进入真实发行页并说明开发预览边界；不存在时才显示源码构建说明，不制造可点击但不可用的下载按钮。
- 支持中英文、桌面与移动布局、键盘访问和减少动态效果；脚本失效时核心文字仍可读。
- SEO 可以在兼容迁移的事实语境中提及 LaunchOS，帮助相关用户发现项目；产品名称、主标题、主视觉和品牌描述保持独立，不暗示隶属关系。
- 只使用 iLaunchPad 自有文案、图标、截图和演示数据；不得复制竞品页面结构细节、演示视频、评价、价格方案或识别性宣传语。
- 官网代码位于 `apps/website/`，规格与产品文档只位于本冲刺；网站目录不维护第二套需求或架构。

## 业务验收

1. 用户能在设置中辨认并选择四款图标，默认与回退均为玻璃蓝；重启、Dock、应用切换器和访达边界符合说明。
2. 新访客无需滚动即可知道 macOS 26、27 缺失了什么、iLaunchPad 如何补回并增强、当前能否直接下载；真实首屏素材未补入时能明确看出该区域仍待拍摄，而非产品画面。
3. 所有演示与案例区要么使用当前版本真实截图/录屏，要么保持有拍摄说明的空白状态；不得出现模拟启动台、旧版画面或虚构应用案例。
4. 站点在桌面和移动视口可读，键盘可操作，减少动态效果生效；没有无效下载、横向溢出或第三方品牌混淆。
5. 两个实现均能从本冲刺规格追溯到文件、任务与验收证据；构建存在不等于视觉或发布验收通过。

## 不在本冲刺

- 官网账号、云同步、支付、订阅、评论、分析与远程客户端控制。
- 签名公证、自动更新和发行流水线；官网只链接已存在的 GitHub Release。
- 复制 LaunchOS、Apple 或其他产品的代码、视觉资产、演示素材及品牌话术。
- 修改冲刺 1 的布局、拖拽、搜索、文件夹和应用移除业务规则。
