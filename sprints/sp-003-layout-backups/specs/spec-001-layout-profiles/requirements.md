# spec-001：Apple 默认布局、自定义备份与安装目录对账

## 产品依据与架构边界

- 对应 [SPRINT-003](../../docs/SPRINT-features.md) F1～F3 和 LAYOUT-01～07。
- 架构基线为 `LayoutStore` 单一 MainActor 布局权威、`layout.json` 原子保存、`ApplicationScanner` 后台扫描和现有原生设置窗口。
- 不改变单进程、本地单用户和无网络依赖架构，不产生 ADR。

## 进入状态

- `layout.json` 是唯一自有布局；启动时自有文件优先，其次尝试 LaunchOS，都不存在时从空布局追加扫描结果。
- 扫描合并只追加新应用，不删除外部卸载后的失效项，不更新已移动应用的路径。
- 应用无用户可管理的布局备份。

## 局部实现方案

### Apple 默认风格布局

`AppleDefaultLayoutFactory` 只消费 `ApplicationScanner` 的完整已安装应用列表：

1. 按 Apple 历史用户指南中可见的 LaunchPad 顺序建立冻结 Bundle ID 优先级：Safari、邮件、联系人、日历、提醒事项、备忘录、地图、信息、FaceTime、Photo Booth、照片、iMovie、库乐队、音乐、图书、App Store、Pages、Numbers、Keynote、预览、词典、计算器、Mission Control、系统设置与 Siri；再按同一产品逻辑补入本机实际存在的新系统应用。
2. 已安装的 Apple Utilities Bundle ID 按冻结顺序组成“其他”文件夹，并为该文件夹保留首页最后一个容量位；首页始终不超过 35 个顶层组。
3. 首页容量之外的优先 Apple 应用先进入第二页，其余未被模板消费的应用按本地化名称排序继续排列，每页最多 35 个顶层组。
4. 应用不存在则不生成占位；至少保留一页。模板只表达 Apple 历史 LaunchPad 的组织习惯，不依赖 Dock 私有数据库或声称 macOS 26、27 公布过固定逐图标清单。

启动时，仅当 `layout.json` 不存在/不可解码且 LaunchOS 自动导入不可用时，才等待首次扫描并生成该布局。设置中的“恢复 Apple 默认布局”使用相同工厂，二次确认后覆盖当前布局，不删除自定义备份。

### 自定义备份文档

新增本地 `layout-backups.json`，版本为 1，包含最多三个有序快照。每份备份包含稳定 ID、名称、创建/更新时间和完整 `LaunchLayout`。

- 新建备份复制当前 `layout`，不修改当前布局。
- 可用当前布局覆盖指定备份，可重命名或删除；名称去除首尾空白且不允许空值。
- 恢复备份时对快照副本做安装目录对账，然后替换 `layout.json`；原备份不被反写，保持快照语义。
- `layout-backups.json` 与 `layout.json` 分别原子替换。备份文档不可解码时不覆盖当前布局，以空备份目录启动并显示错误。

### 安装目录对账

可单测纯函数输入候选 `LaunchLayout` 和完整已安装应用列表：

1. 以非空 Bundle ID 为主键，无 Bundle ID 时使用标准化路径。
2. 存量应用如仍安装，保留布局 ID 和 `hidden`，使用扫描结果更新名称、Bundle ID 和路径。
3. 不在扫描结果中的应用移除；空组移除，单成员文件夹转普通组，空页收尾但至少保留一页。
4. 新应用按本地化名称顺序追加到首个不足 35 个顶层组的页，全满才新建页。
5. 目录监听、手动刷新、唤起核对与恢复备份共用同一规则。被取消的空扫描结果不触发删除。

### 恢复事务与设置交互

- 拖拽预览中拒绝恢复。操作开始后标记 busy，后台扫描完整应用目录；扫描返回空列表时保留现状并报错。
- 只有候选布局对账成功后才一次发布新 `layout`、清空图标缓存并保存。成功通知主界面关闭文件夹、清空搜索/选择并夹紧当前页，不重放 spread。
- 设置新增“布局”标签：Apple 默认初始化、备份当前布局、恢复/覆盖/重命名/删除自定义备份。初始化、覆盖和删除都用 `NSAlert` 二次确认，命名用 `NSAlert` 文本输入，busy 时禁用全部操作。

## 退出状态

- 无布局来源的新用户自动获得 Apple 默认风格布局，用户可在设置中重新执行。
- 用户可保存、覆盖、重命名、恢复和删除最多 3 份快照。
- 恢复与日常刷新都及时反映已卸载、新安装和路径变化，修复“贝锐向日葵已删除仍显示”类问题。

## 临时实现与收口

无 Mock、远程接口或后续收口规格。`layout.json` 继续是当前布局权威，`layout-backups.json` 只保存用户快照。

## 验收条件

- 隔离测试覆盖无来源默认初始化、3 份上限、新建/覆盖/重命名/删除/恢复和重启持久化。
- 对账测试覆盖已卸载删除、元数据更新、新应用最近首页追加、文件夹收尾与存量顺序不变。
- release 构建与签名通过并自动安装；真实设置操作和布局正确性由人工验收。
