# 核心业务流程

业务规则权威在 [SPRINT-features.md](SPRINT-features.md)，实现时序在 spec-005；本页呈现用户流程，不记录缺陷处理历史。

## 使用闭环（ASCII）

```text
唤起 → 隐藏 Dock → 浏览 / 搜索 → 选择应用 → 启动 → 关闭并恢复 Dock
                    │
                    ├→ 打开文件夹 → 改名 / 浏览成员 / 返回
                    └→ 长按编辑 / 拖拽 → 预览 → 合法松手 → 保存
                                             └→ 取消/失败 → 撤销
```

## 布局来源（ASCII）

```text
启动 → 自身布局有效？ ─是→ 恢复 → 发现新增应用
          │否
          └→ 选择可用来源 / 无来源建立初始布局
                 ├→ LaunchOS（现有兼容数据库可自动只读迁移）
                 └→ macOS 26 以前系统 Launchpad（遗留数据 / 备份）

主动导入 → 明确来源 → 只读解析与匹配 → 完整校验 → 覆盖确认与恢复副本 → 替换保存
                      └→ 缺失/不支持/不完整 ───────────────→ 报错并保留当前布局
                                           取消 ───────→ 保留当前布局
```

这是目标流程；当前只实现的部分及差距见 spec-001/tasks，不把目标写成运行架构事实。旧系统升级后源数据可能不存在；没有源或备份就不能重建用户的原排序。

## 连续整理（ASCII）

```text
起拖并保存快照
  → 当前鼠标位置
      ├→ 顶层外围格子：意图停留 → 换位
      ├→ 普通App中心：稳定重叠 → 临时建组并展开 → 组内换位
      │                                      ├→ 拖出：撤销临时合组 → 外部继续
      │                                      └→ 组内松手：保留并提交 → 聚焦名称
      ├→ 组图标内：短停留选中 → 长停留展开 → 进入组内换位
      │                                      └→ 有意拖出 → 收组 → 返回顶层
      └→ 屏幕边缘：停留切页 → 返回位置判断
  → 每次位置变化继续判断，直到松手
      ├→ 合法当前落点：原生接收 → 最终重算 → 提交一次 → 保存
      └→ 取消/失效：恢复整个快照
```

图标显示、容器位置和持久化是同一手势的三个方面；重建目标格不等于新起拖，开组不等于提交，源结束回调不等于用户选择取消。

## 管理动作（ASCII）

```text
隐藏 → 改可见性 → 保存（文件保留）
移出组 → 改容器 → 空组移除 / 单成员组解散 → 保存（应用保留）
卸载 → 资格检查 → 确认 → 资格复验 → 移入废纸篓 → 清除布局 → 保存
           └不允许      └取消      └变化/运行中/失败 → 不删除并反馈
```

卸载应用包和保存 JSON 不是跨文件事务；后一步失败必须单独反馈。导入、卸载与拖拽预览不能互相覆盖未结束的用户操作；具体并发限制应在所属规格落实。
