# iLaunchPad 产品概览

iLaunchPad 是为 macOS 26、27 补回 Launchpad 的本地原生应用启动器。它先恢复用户熟悉的全屏应用网格、页面、文件夹、搜索与拖拽整理，再以现代 macOS 系统组件、连续交互和本地布局能力重新打磨体验，并为后续高级能力保留扩展空间。这里定义产品目标，当前支持程度见 README 和对应规格。

“把缺失的 Launchpad 基础能力补回来”和“把外观与操作体验提升到现代 macOS 水准”是两个连续但独立的目标。不能以做出相似网格代替完整交互，也不能以构建成功代替顺滑度和系统质感验收。未来高级功能必须建立在基础启动台稳定可用之上，并在对应冲刺中单独定义，不能提前宣传成现有能力。

项目面向开源社区，以 MIT 许可降低使用和参与门槛；同时作为 SpecRocket 规格驱动开发的实践案例，让功能、实现与验收可追溯。传播建立在真实体验与透明边界上，不以“零 bug”或未经测量的性能作为宣传承诺。

## 用户与价值

| 用户 | 核心需要 |
|:---|:---|
| 习惯图标位置与文件夹分类的 Mac 用户 | 保持空间记忆，快速找到并打开应用 |
| 已使用 LaunchOS、LaunchNext 等兼容启动器完成排序的用户 | 经明确选择后延续页面、组内顺序与名称，无须重新整理 |
| 保留旧系统 Launchpad 数据或备份的用户 | 恢复升级前的页序、文件夹与应用位置，不依赖旧系统仍能运行 |
| 偏好系统原生界面的用户 | 原生输入、菜单、液态玻璃及连续过渡 |
| 初次了解项目的访客与开源贡献者 | 在官网首屏理解产品用途、真实能力、获取状态，并只从真实客户端素材判断体验 |

## 核心场景

用户唤起启动台，浏览或搜索应用，打开后回到工作；整理时拖动图标换位、跨页或进入/离开文件夹，松手确定，取消恢复原布局。编辑模式通过长按进入，系统组件不显示卸载按钮；允许管理的应用统一二次确认并移入废纸篓。启动台打开时隐藏 Dock，关闭或切到其他应用时恢复。

两个 App 合组也遵循连续预览：经过不合组、外围停留可换位、图标重叠停留达到阈值后生成并展开临时组；不松手可组内换位或拖出还原，组内松手才保留新组并进入命名。成员减少到一个的组自动解散，剩余 App 留在原组位置；解散不等于卸载。

## 功能板块

| 板块 | 用户能力 | 边界 |
|:---|:---|:---|
| 应用目录与布局 | 发现应用、保留排序、从受支持的第三方来源或旧系统 Launchpad 继承布局 | 三类来源只读，不双向同步或修改源数据 |
| 唤起与系统集成 | 打开/关闭启动台、回到原工作、正确处理 Dock 与焦点；可选登录时后台启动 | 不替换系统 Dock，不改系统安全配置；登录项由用户主动开启 |
| 查找与启动 | 图标浏览、分页、搜索、键盘选择、启动应用；缓存加速再次打开 | 搜索结果与资源缓存都不是新的布局 |
| 文件夹 | 创建、展开、命名、关闭、访问全部内容 | 单层分类，不嵌套文件夹 |
| 拖拽与排序 | 同页/跨页、组内/组外连续整理，提交或取消 | 一次拖拽是一项可撤销的完整操作 |
| 编辑与应用管理 | 长按编辑、隐藏、显示隐藏项、访达定位、确认卸载 | 隐藏不卸载；卸载不清理个人数据 |
| 外观与使用偏好 | 图标大小、名称、壁纸模糊、起始页选择、登录启动开关与系统状态 | 系统原生风格，不提供任意换肤引擎 |
| 品牌标识与官网 | 选择项目原创应用标识；通过独立产品官网理解、查看真实体验并获取项目 | 不复制第三方视觉资产；官网不读取客户端布局，不用网页模拟画面冒充客户端 |

基础启动台细功能见[冲刺 1](../sprints/sp-001-native-launchpad/docs/functional-overview.md)，品牌标识与官网见[冲刺 2](../sprints/sp-002-brand-and-website/docs/functional-overview.md)。一个功能板块对应一个规格，板块中的 bug 回到该规格维护，不再每次报错新增规格。

## 产品边界

本地单用户应用，无账户、服务器、订阅校验或云同步。LaunchOS 与 LaunchNext 数据兼容仅用于一次性只读迁移，旧系统 Launchpad 数据是另一类独立来源；无源数据或备份时不承诺恢复原位置。对外产品描述不使用“复刻”“完美还原”“像素级一致”等容易造成来源、授权或兼容范围误解的表述。iLaunchPad 不复制其他产品的代码、文案、素材、评价或品牌识别，也不暗示与 Apple 或其他启动器存在隶属、授权或背书关系。

iLaunchPad 的移除操作只把应用包移入废纸篓，不主动清理个人文稿、设置、缓存或辅助文件，也不取消订阅。应用能力进度与缺口统一见根 README，逐项证据仅在规格 tasks/check 维护。

客户端和官网是两个独立交付面：客户端为 macOS 26、27 用户补回并增强 Launchpad；官网必须先讲清这一缺口，再展示现代外观、连续整理、本地布局和后续扩展方向。官网只展示项目原创内容、真实客户端截图/录屏和真实获取状态，不与客户端交换用户数据。官网框架确定但素材尚未拍摄时，使用明确标注用途、尺寸和拍摄内容的空白槽，不使用网页绘制的启动台或虚构案例代替证据。冲刺 1 的目标是基础原生启动台功能，冲刺 2 承接应用图标设计实现与官网设计实现。当前代码未实现的目标能力须明确列出，不得从需求中静默删除。

## 术语

| 术语 | 含义 |
|:---|:---|
| 页面 | 启动台中的一屏有序图标 |
| App 组 / 文件夹 | 包含有序应用的单层容器 |
| 普通应用格 | 包含一个应用的顶层布局单元 |
| 拖拽预览 | 鼠标未松开时的可取消内存布局 |
| 意图停留 | 用短暂停留区分经过、换位、选中和展开 |
| 布局恢复 | 读取兼容的 LaunchOS、LaunchNext 布局或旧系统 Launchpad 数据，经确认后替换自身排序 |
