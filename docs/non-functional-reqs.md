# 非功能约束

## 平台与实现

应用采用 Swift 6、SwiftUI 与 AppKit，最低 macOS 26.0；现有打包脚本生成 arm64 应用。系统 API 和组件优先：NSCollectionView、NSSearchField、NSGlassEffectView、NSAlert、NSWorkspace。UI 目标是用户要求的现代 macOS 液态玻璃质感；部署兼容下限不等于视觉验收结论。

## 性能与可用性

拖动、翻页和文件夹过渡应连续、可中断，不出现硬边遮挡、错层或重复图标。重排必须持续跟随当前鼠标位置；昂贵资源应缓存，搜索索引异步生成。遵循系统“减少动态效果”。这些是体验要求，不能用编译成功替代实机验收；没有已测得的帧率、SLA 或启动时间承诺。

连续操作比单步点击更重要：打开动画未结束、按住不放、反复进出组、快速换位、翻页后接着拖动和最终松手都属于同一功能的正常路径。输入响应、动画与数据提交不能各自维护互相冲突的状态。

启动优化区分无缓存首次启动、已有磁盘缓存的新进程启动、常驻进程再次唤起。图标预解码、壁纸处理、目录扫描不在开场动画期间集中占用主线程；优先当前页，再准备邻页和其余资源。内存与磁盘缓存必须有容量上限、失效键及错误回退，缓存可删除重建但不能作为布局来源或覆盖排序。

高频交互优先使用 AppKit 原生输入、Core Animation 合成及当前窗口的显示同步时钟；不把固定60次计时器冒充高刷适配，也不通过常驻120次计时器耗电。SwiftUI 系统控件仍属原生技术，是否替换依据测量到的热点，不按代码占比决定。隐藏窗口及拖拽结束后停止对应刷新工作，遵循系统动态刷新率、节能及减少动态效果。

性能验证记录实际显示器、刷新能力、系统节能状态、样本数与缓存状态；分别测启动可交互时间、主线程长任务及真实呈现帧时/卡顿。120Hz 的单帧预算约8.33ms，60Hz约16.67ms，这是测量参考而非达标结论。显示回调次数、截图、最高刷新率和构建通过都不能替代实际呈现数据。

官网为无服务端依赖的静态站点，核心说明、素材状态与获取入口在脚本失效时仍应可读；常见桌面与移动视口不得横向溢出。客户端体验只能使用同一版本真实截图或录屏证明；框架阶段用有文字标注的空白素材槽，禁止用 HTML/CSS 仿造启动台、虚构应用案例或旧版画面填充。图片按实际展示尺寸提供，首屏不依赖自动播放视频或大型第三方脚本。键盘焦点、对比度、语义标题和 `prefers-reduced-motion` 属于发布前验收项。

## 交互与可访问性

鼠标、触控板和键盘应能完成各自声明支持的操作。搜索与文件夹命名保留输入法组合文本和光标编辑；系统弹窗出现时不截获其正常输入。可点击区域与可见组件一致，装饰效果不扩大文件夹加入区域。名称隐藏、窗口缩放/换屏及减少动态效果不能导致应用不可定位。VoiceOver 等完整辅助功能覆盖需专项验收，不从使用系统控件直接推断合格。

## 数据与安全

拖拽未提交期间不写布局文件；取消恢复起始快照。保存采用原子文件替换。LaunchOS 与旧系统 Launchpad 数据均只读接入；完整校验后才替换自身布局，覆盖前应保留恢复副本。应用运行无需网络凭据，布局与本地应用路径不上传。卸载必须验证应用位置、身份和文件可删除性，并再次确认；禁止删除系统组件、自身、运行中的应用和嵌套 helper。确认后只使用系统废纸篓 API 移动应用包，不执行外部卸载程序、脚本、私有卸载 API，也不扩大到个人文稿、设置、缓存或辅助文件。
