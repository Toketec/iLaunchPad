# 产品定位

## Launchpad 消失以后，熟悉的位置仍然重要

macOS 26、27 不再提供用户熟悉的 Launchpad，但以图标、页面和文件夹整理应用的空间记忆并没有消失。iLaunchPad 的第一使命就是补回这条入口：打开启动台，找到熟悉的位置，启动应用，回到工作。

产品不会停在“恢复旧功能”。现代系统材质、连续拖拽、搜索、本地布局、兼容迁移和后续高级能力，都服务于把这条熟悉路径做得更漂亮、更顺滑、更可靠，而不是增加新的学习负担。未来能力以独立规格逐步落地，不把路线图当作现成功能宣传。

布局保存在用户自己的电脑上。兼容 macOS 遗留数据、LaunchOS 与 LaunchNext 的迁移价值，是减少重新整理的成本，而不是让用户继续依赖另一个启动器。基础功能完整性、安全的数据处理与顺滑体验，优先于堆叠新功能；产品范围以 [产品概览](product-overview.md) 为准。

## 一个可以追溯过程的开源作品

项目以 MIT 许可面向开源社区，欢迎使用、研究与贡献。它也是 SpecRocket 的实践案例：不仅展示一个可运行的应用，还公开需求如何拆成细功能、功能如何进入规格、实现如何接受验证。

项目从已有原型迁入规格驱动开发，并非从第一行代码起就采用该流程。这个事实本身值得保留：规格的作用不是给已有结果贴标签，而是把遗漏的边界补齐，让后续修改有共同依据。不能把“使用了 SpecRocket”当作体验达标或没有缺陷的证明。

## 开放传播与持续维护

MIT 允许商业使用和再分发，也允许他人售卖副本；项目接受这一传播取舍。持续维护的价值来自官方版本的质量、可信发布、社区协作和支持，而不是假设代码不可复制。赞助、支持服务或便利的发行渠道可以作为未来探索方向，但不在此承诺收费策略或收入。

## 独立品牌与原创传播

iLaunchPad 从 Mac 用户真实的应用查找与整理需求出发，不以“复刻某个商业产品”作为品牌定位。官网和公开材料聚焦本地优先、空间记忆、连续整理、原生系统组件与可追溯开发过程；迁移兼容只是降低切换成本的能力，不成为借用其他品牌影响力的宣传主轴。

同类产品的成功可以帮助理解用户关心什么，但最终表达必须由 iLaunchPad 自己完成：使用自己的标题、当前版本真实截图与录屏、图标和事实证据，并清楚说明这是独立开源项目。素材尚未完成时宁可展示明确标注的空白拍摄位，也不用网页模拟或旧版画面代替。对 Apple、macOS、第三方启动器及其商标的提及只用于准确描述平台或兼容事实，不暗示合作、授权或背书。

客户端与官网共同表达同一产品，但职责分离：客户端解决本机应用查找与整理，官网负责让访客快速理解价值、查看真实产品证据并进入公开源码或发行入口。官网不成为客户端账号、遥测或布局同步的入口。
